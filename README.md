# COLOR CLASH — Arcade & Balance Update

2026-11-04 수정본입니다. 메인 타이포그래피, 모드 선택, 배틀 화면을 고도화하고 경쟁용 목표 색 밸런스를 수정했습니다. 브라우저 검증 결과와 스크린샷은 `UPDATE-REPORT.md`, `screenshots/`에 있습니다.

## 바로 실행

압축을 풀고 `PLAY.html`을 Chrome/Edge에서 여세요. 코드·로고·영문/한글 폰트가 내장되어 있어 로컬 배틀·팀 배틀·실험실·튜토리얼에 별도 설치가 필요 없습니다. 온라인 대전은 HTTPS 호스팅과 Firebase 규칙 적용이 필요합니다.

`PLAY.html`은 실제 Chromium에서 HTTP 미리보기로 열어 폰트·CSS·버튼 동작을 검증했습니다. 파일을 더블클릭한 `file://` 환경은 직접 검증하지 않았습니다.

## 규칙

- 1대1: RED/BLUE 각 14회. 물감 한 방울·제출·비우기·넘기기 각각 행동 1회. 목표와 접시 선택은 무료.
- 접시 2개, 접시당 최대 6방울. 제출 시 그 접시만 비웁니다.
- 목표 100/150/200점. 유사도 80 이상 획득, 95 이상 +25점.
- FINAL COLOR: 새 목표, 각자 최대 5방울, 더 정확한 쪽 +200점. 동점은 각 +100점.
- 2대2: RED A → BLUE A → RED B → BLUE B, 개인 8회, 팀 16회. A/B 담당 접시 분리. 결승전은 팀원 정확도 평균을 비교.

## 새 목표 생성 규칙

전체 461개 배합에서 축약한 358개 색 중, 경쟁에 적합한 295개 색을 사용합니다. EASY/NORMAL/HARD 후보는 11/93/191개입니다.

단색 한 방울만으로 유사도 80점에 도달할 수 있는 색은 **모든 경쟁 목표**에서 제외합니다. 원본 레시피가 복잡하더라도 단색으로 쉽게 획득할 수 있으면 제외합니다. 시작 3장과 교체 목표, 결승전에 같은 필터가 적용됩니다. 튜토리얼과 자유 혼합은 기존 규칙입니다.

시작 카드는 쉬움/보통/어려움 각 1장입니다. 실제 생성 가능한 배합을 사용하고 서로 지각적으로 구별되는 색을 선택합니다. 정확도 95 이상을 만드는 최소 배합의 방울 수·물감 종류로 난이도를 정합니다. 구체적인 예시는 `balance-examples.json`과 UPDATE-REPORT.md에 있습니다.

이 수정은 한 방울 단색 선점 원인을 제거합니다. 전체 선공/후공 승률이 동일하다는 의미는 아니며, 실제 학생 반복 플레이를 통한 승률 검증은 아직 하지 않았습니다.

## 개발·빌드·검사

Node 22 이상 권장.

```sh
npm ci
npm run dev
```

프로덕션:

```sh
npm run build
npm start
```

PORT 환경변수를 사용하며 기본값은 3000입니다. Node 서버는 dist 정적 파일을 제공합니다.

```sh
npm test
npm run build:offline
npm run test:css
npm run test:ui
npm run test:rules:rest
```

게임/밸런스 15개, CSS/폰트 4개, 생성 HTML React DOM 6개, Firebase 에뮬레이터 REST 3개, 총 **28개 자동 테스트**를 통과했습니다. 보안 에뮬레이터에는 Java 21+가 필요합니다. `test:rules` SDK WebSocket 경로는 이전 환경에서 미완료였고, 검증된 보안 테스트 경로는 `test:rules:rest`입니다.

`.qa/viewport.html`은 개발 전용 브라우저 검증 페이지로 게임을 정확한 CSS viewport 크기의 iframe에서 실행합니다. Vite 서버에서만 사용하며 dist에는 들어가지 않습니다. PC 캡처는 전체 화면이 보이도록 검증 틀만 축소 표시하며 게임 내부 CSS viewport는 1440×900으로 유지합니다.

브라우저 권한이 있는 사용자 컴퓨터에서는 아래 보조 스크립트도 사용할 수 있습니다. 이 스크립트 자체의 전체 실행은 이번 검증에서 사용하지 않았으며, 실제 검증은 지원되는 클라우드 브라우저에서 수행했습니다.

```sh
npm install -D playwright
npx playwright install chromium
npm run test:browser
```

## Firebase — 기존 프로젝트 유지

프로젝트 ID는 `color-crash-game`, 설정은 src/firebaseConfig.ts입니다. 기존 설정·보안 규칙·게임 데이터 모델을 바꾸거나 실제 데이터를 초기화하지 않았습니다.

1. Firebase Console에서 기존 프로젝트를 엽니다.
2. Realtime Database → 규칙에서 현재 규칙을 백업합니다.
3. 초기 잠금 규칙만 있다면 database.rules.json 전체를 게시합니다. 다른 앱의 규칙이 있다면 전체 교체하지 말고 rules.cc 아래만 병합합니다.
4. Authentication → 로그인 방법 → 익명 사용을 확인합니다.
5. Onpod에 실제 배포 후 승인된 도메인과 별도 API 키 referrer 제한이 있다면 해당 호스트를 확인합니다.
6. 서로 다른 기기/브라우저 프로필에서 한쪽이 방 생성, 다른 쪽이 6자리 코드 입력 후 참가합니다. 모두 READY 후 방장이 시작합니다.

동일 브라우저의 익명 UID를 사용해 복귀합니다. 새로고침 후 ONLINE BATTLE의 복귀 버튼을 사용하세요. 상대 연결 종료는 표시하고 상태를 보존합니다. 결승전 제출 원본은 제출했던 브라우저 저장소가 필요합니다. 저장 데이터를 삭제하거나 기기를 바꾸면 제출 원본 복구가 불가능합니다.

온라인 결승전은 SHA-256 확정 후 모두 확정되면 공개하며 클라이언트가 해시를 검사합니다. 보안 규칙은 멤버 접근, 본인 자리, 차례, revision, 값 범위, 공개 시점을 제한합니다. 색 판정과 모든 상태 변경을 서버가 완전히 재계산하지 않으므로 변조된 클라이언트의 모든 부정행위를 막지는 못합니다. 목표 레시피도 클라이언트 데이터입니다.

개인정보는 실명·학교·이메일 없이 익명 UID를 사용합니다. 장기 보관이 필요 없는 방은 수업 후 콘솔에서 해당 코드의 cc/meta, members, games, presence, finals 아래 데이터만 정리하세요. 자동 정리는 구현하지 않았습니다.

실제 Firebase 온라인 두/네 기기 대전은 이번에도 검증하지 않았습니다. 기존 프로젝트의 콘솔 규칙도 직접 게시하지 않았습니다.

## Onpod 배포

배포 플랫폼은 Onpod, 온라인 저장은 기존 Firebase입니다. Firebase Hosting으로 바꾸지 않았습니다. Onpod 인증이 연결되어 있지 않아 미배포이며 실제 URL은 없습니다. 서버 파일, Dockerfile, dist는 포함되어 있습니다.

사용자 컴퓨터에서 공식 https://onpod.ai/mcp 안내에 따라 CLI를 설치·인증하고 프로젝트 폴더에서 `npm run build` → `onpod deploy`를 진행하세요. 우선 dist 정적 배포를 선택합니다. 무료/₩0 제안을 확인한 뒤 실행하고 유료 자원으로 변경하지 마세요. 비밀 토큰은 채팅에 보내지 마세요.
